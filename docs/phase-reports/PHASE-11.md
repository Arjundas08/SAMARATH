## 1. Executive Summary

Phase 11 delivers the centerpiece operational user interface for the SAMARATH platform per Blueprint Sections 31–32 and the "Signal & Slate" design specifications. Designed specifically for Chief Train Controllers (CPTM/CFTM), Divisional Railway Managers (DRM), and Senior Divisional Engineers (Sr.DEN), the Operational Planning Workbench renders multi-department track possessions alongside live Working Time Table (WTT) train paths on an interactive Time-Distance string chart, backed by real backend solver orchestration and independent oracle verification.

### Key Capabilities & Invariants Delivered:
1. **Interactive Time-Distance String Chart (ECharts):**
   - Horizontal time axis formatted in `Asia/Kolkata` (IST) across 7-day or 24-hour selectable views.
   - Vertical spatial axis spanning chainage Km 0.0 to Km 120.0 with 6 corridor stations (Alpha, Bravo, Charlie, Delta, Echo, Foxtrot) and bidirectional track segments (UP/DOWN).
   - Real train path trajectories from `train_timetable.json` differentiated by service type (Passenger, Express, Freight).
   - Maintenance block packages rendered as colored geometric rectangles with visual indicators for setup/work/restoration phases, power blocks (⚡), and hard locks (🔒).
2. **Synchronized 3-Column Layout:**
   - **Left Column (270px):** Maintenance Queue featuring real-time search, status filtering (All, Placed, Unplaced, Locked), department filters (ENG, ELE, S&T), and instant selection synchronization.
   - **Center Column (Fluid):** Primary Canvas supporting 3 specialized operational view modes:
     - *Time-Distance Canvas:* String chart with zoom, pan, reset, and direction toggles.
     - *Machinery Gantt:* Timeline tracking heavy track machines (BCM-01, CSM-01, Tower Wagon TW-01) and engineering maintenance gangs.
     - *Accessible Table:* WCAG-compliant sortable and filterable data table with oracle verdicts.
   - **Right Context (Evidence Drawer):** Deep contextual inspection panel presenting work phases, electrical section isolations, machinery allocations, 9 readiness dimensions, and independent Phase 07 Oracle validation.
3. **Dual-Horizon Planning:**
   - Seamless toggling between **Weekly Execution (7D)** and **Tactical Monthly (30D)**.
   - Monthly Allocation view features a 4-week calendar grid (Weeks 1 to 4), departmental possession quota meters (minutes and machine days), provisional placement badges, and active reconciliation warning banners.
4. **Live Asynchronous Solve Orchestration:**
   - Connected to Phase 10 leased worker queue via `POST /api/v1/planning/solve-jobs/{job_id}/execute`.
   - Real-time phase progression streaming: `QUEUED` → `CLAIMED` → `OPTIMIZING_BASE` → `OPTIMIZING_STAGES` → `RUNNING_CHECKER` → `PUBLISHING` → `COMPLETED`.
   - Instant re-rendering upon completion with newly materialized plan versions and assignment IDs.
5. **Zero Mock Data Invariant:**
   - All spatial geometry derived from `corridor_topology.json`.
   - Train trajectories derived from `train_timetable.json`.
   - Block allocations generated by the OR-Tools CP-SAT multi-stage optimizer and verified by the independent Phase 07 Python checker.

## 2. Architecture & Implementation Details

### 2.1 Backend Support Endpoints (`backend/app/api/v1/planning.py`)
- `GET /api/v1/planning/timetable/occupations`: Serves authentic train timetable occupations with start/end minutes, train numbers, and segment bounds.
- `GET /api/v1/planning/corridor/topology`: Serves corridor stations, chainage km, and track segment attributes.
- `POST /api/v1/planning/solve-jobs/{job_id}/execute`: Initiates asynchronous leased worker execution for workbench solver runs.

### 2.2 Frontend API Client & Types (`frontend/src/types/api.ts`, `frontend/src/api/solveJobs.ts`)
- Added comprehensive TypeScript interfaces:
  - `StationInfo`, `TrackSegmentInfo`, `CorridorTopologyResponse`.
  - `WorkPhaseSchedule`, `ResourceAllocation`.
  - `MonthlyAllocationPlan`, `WeeklyPlanSummary`, `DepartmentQuotaStatus`, `ReconciliationCase`.
- Implemented `SolveJobApi` methods:
  - `getTopology`, `getOccupations`, `listPlans`, `executeJob`, `listMonthlyPlans`, `allocateMonthlyPlan`, `getReconciliationCases`.
